# Darning simulator

A visible, comparative simulator for damage, darning, traditional star darning, and sashiko-style reinforcement in an effectively infinite woven sheet.

**Live exhibit:** <https://domenzain.github.io/darning-simulator/>

The numerical and geometric core is Rust. The same crate builds as:

- a native library and SVG-producing command-line program;
- a 75 KiB freestanding WebAssembly module with no `wasm-bindgen`, JavaScript model, package-manager dependency, or runtime framework.

The browser sends flat configuration buffers to the Rust module in a Web Worker, so simulation and WebAssembly compilation do not block interaction with the page.

## What it does

- orthotropic base tissue with separate warp and weft directional capacities;
- exact null damage, worn ellipses, holes, and tears;
- elliptical, rectangular, or interactively drawn concave repair perimeters;
- plain and basket darning, running sashiko, hishi, asanoha-inspired reinforcement, and a traditional woven-wheel star darn;
- common polygon clipping for every pattern;
- stitch paths aligned to interstitial channels in the base weave where applicable;
- local directional-strength heat maps under a selectable pull direction;
- an automatically enlarged computational domain whose boundary perturbation is below the selected far-field tolerance;
- native SVG rendering and direct WebAssembly, worker, HTTP-serving, and mechanics tests.

## Star darn

The star repair was selected by comparing a rendered geometry prototype against photographs and stitch instructions before writing the Rust generator. It uses radial foundation threads followed by a compact centre worked in the repair-specific under-two/back-over-one cadence. It is not an ordinary left/right darn clipped into a star silhouette.

See [`docs/star-darn.md`](docs/star-darn.md) and the [preview generated by the Rust core](docs/star-darn-preview.svg).

## Local development

The project has no third-party Rust or JavaScript dependencies.

```sh
rustup target add wasm32-unknown-unknown
npm test
npm start
# open http://127.0.0.1:8000/darning-simulator/
```

`npm test` runs formatting, Clippy with warnings denied, native unit tests, a release WebAssembly build, JavaScript syntax checks, direct WebAssembly smoke tests, the real browser-worker protocol under Node, an HTTP/MIME deployment smoke test, and native SVG rendering.

The shortest iteration loop is:

```sh
cargo test
./scripts/build_wasm.sh
node tests/wasm_smoke.mjs
```

## Native rendering

```sh
cargo run --release --bin darning-render -- \
  --pattern star \
  --damage hole \
  --output repair.svg
```

Accepted pattern names are `none`, `darn`, `basket`, `running`, `hishi`, `asanoha`, and `star`. Damage names are `none`, `wear`, `hole`, and `tear`.

## Performance

The release module is currently about 75 KiB. In the local validation environment, the default `129²` star simulation took about 28–30 ms both directly and through the actual Web Worker message path. The worker makes this asynchronous from the UI; the `161²` and `193²` settings remain available for finer inspection.

## Model

For unit pull direction `n`, warp direction `w`, and weft direction `f`, the intact directional capacity is

```text
C₀(n) = Cw (n·w)² + Cf (n·f)².
```

Damage removes local capacity. Stitches deposit capacity according to their tangent relative to the pull direction. A screened load-transfer solve propagates that signed perturbation:

```text
(I − ℓ²∇²)u = s.
```

The finite domain is enlarged in multiples of the transfer length `ℓ` until the omitted tail is below the requested tolerance. Full assumptions and limitations are in [`docs/model.md`](docs/model.md).

The result is a comparative local-strength proxy, not a certified tear, seam, fatigue, or fracture-mechanics calculation.

## Architecture

- `src/lib.rs`: geometry, pattern registry, clipping, stitch rasterization, screened solve, metrics, and a flat C ABI for WebAssembly.
- `src/bin/render_svg.rs`: native renderer using the same Rust simulation function.
- `darning-simulator/worker.js`: small WebAssembly-loader and buffer bridge.
- `darning-simulator/app.js`: controls and canvas rendering only.
- `tests/`: invariants, binary validation, worker protocol, and served-site checks.

New decorative patterns implement one Rust generator that emits segments. The common clipper and mechanics path handle arbitrary repair perimeters without pattern-specific solver code.
